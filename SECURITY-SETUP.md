# Інструкція з впровадження виправлень безпеки

Що було зроблено та що вам потрібно зробити, щоб це запрацювало на реальному Firebase-проєкті.

## Що виправлено в коді

1. **Паролі більше ніде не зберігаються у відкритому вигляді.** Замість самописної
   перевірки `pass === введений_пароль` тепер використовується Firebase Authentication —
   пароль ніколи не потрапляє в Realtime Database і не лежить у `localStorage`.
2. **База даних більше не відкрита для запису будь-ким.** Раніше будь-хто міг через
   `fetch()`/`curl` переписати дані будь-якого гравця (бали, покупки, друзів). Тепер
   запис у `users/{uid}` дозволений лише власнику акаунта — це закріплено в
   `database.rules.json`.
3. **Особисте листування з підтримкою тепер приватне.** Раніше `supportMessages`
   зберігалися прямо всередині публічного профілю гравця й були доступні для читання
   будь-кому. Тепер це окрема гілка `support/{uid}`, яку може читати тільки сам гравець.
4. **Пошук гравців за ніком** (друзі, топ, профіль) тепер іде через окремий індекс
   `nicknames/{нік} → uid`, а не напряму по нікнейму як ключу бази — це і безпечніше,
   і дозволяє прибрати старий відкритий доступ.
5. **Захист від XSS.** Ніки та інші дані, введені гравцями, тепер екрануються
   (`escapeHtml`) перед вставкою в сторінку — зловмисний нік на кшталт `<img onerror=...>`
   більше не виконається в чужому браузері.
6. Прибрано мертвий файл `js/friends.js` (його функції все одно перезаписувались
   файлом `js/cabinet.js`, який підключався пізніше).

## Що потрібно зробити вам (обов'язково, по порядку)

### 1. Увімкнути Email/Password вхід у Firebase
Firebase Console → ваш проєкт → **Authentication** → **Sign-in method** →
увімкнути провайдер **Email/Password**.

### 2. Отримати конфігурацію веб-застосунку
Firebase Console → **Project settings** (шестерня) → вкладка **General** →
розділ **Your apps** → ваш Web app → **SDK setup and configuration** → скопіювати
значення `apiKey`, `appId`, `messagingSenderId`, `storageBucket`.

Вставити їх у файл **`js/firebase-config.js`** замість `"ВСТАВТЕ_СЮДИ..."`.
`databaseURL` там уже підставлено з вашого поточного проєкту.

### 3. Заблокувати старі правила бази (терміново, до будь-яких інших кроків)
Firebase Console → **Realtime Database** → вкладка **Rules** → тимчасово поставити:
```json
{ "rules": { ".read": false, ".write": false } }
```
і натиснути **Publish**. Це негайно закриє відкритий доступ, поки триває міграція.
Admin SDK (наступний крок) працює незалежно від цих правил, тож міграції це не завадить.

### 4. Мігрувати наявних гравців (скрипт `scripts/migrate-to-firebase-auth.js`)
```bash
cd scripts
npm install
```
Отримати сервісний ключ: Firebase Console → **Project settings** → **Service accounts** →
**Generate new private key** → зберегти файл як `scripts/serviceAccountKey.json`
(він уже додано в `.gitignore`, у репозиторій не потрапить).

Спочатку прогнати без реальних змін:
```bash
node migrate-to-firebase-auth.js --dry-run
```
Перевірити лог, і якщо все виглядає нормально — запустити насправді:
```bash
node migrate-to-firebase-auth.js
```
Скрипт створить Firebase Auth-акаунт для кожного гравця з його поточним паролем,
перенесе профіль на `users/{uid}` без поля `pass` і збереже локальний бекап
(`scripts/legacy-users-backup.json`) про всяк випадок.

⚠️ Гравці зі старими паролями коротшими за 6 символів будуть пропущені
(Firebase Auth вимагає мінімум 6) — їм доведеться зареєструватися заново під тим самим
ніком або звернутися до вас за скиданням.

### 5. Опублікувати нові правила бази
Вміст файлу `database.rules.json` із цього репозиторію вставити в
Firebase Console → **Realtime Database** → **Rules** → **Publish**.

### 6. Викласти новий код гри (index.html + js/*) на хостинг
Переконайтеся, що `js/firebase-config.js` вже заповнений реальними значеннями
(крок 2), перш ніж викладати.

### 7. Перевірити вхід кількох реальних гравців
Попросіть 2-3 людей увійти під своїми старими логін/паролем і переконатися,
що все працює: вхід, гра, магазин, друзі, підтримка.

### 8. Прибрати старі дані з паролями
Після успішної перевірки:
```bash
node migrate-to-firebase-auth.js --cleanup
```
Це остаточно видалить стару гілку `users/{нік}` з паролями відкритим текстом
з бази даних.

## Якщо є сумніви, що дані вже витекли

Оскільки база була відкрита для читання/запису без обмежень, варто виходити з
припущення, що дані (включно з паролями) вже могли бути прочитані сторонніми.
Після міграції варто:
- Попросити гравців, які використовують той самий пароль десь ще, змінити його і там теж.
- Слідкувати за підозрілою активністю (різкі стрибки балансу, дивні покупки).
